源码核对日期：2026-09-19。本文描述当前实现，不是规划中的目标架构。

## 1. 定位与系统边界

书内 / BOOKNOTE 是按教材范围约束回答的多账户课程学习助手。账户可以读取共享内置书，或上传自己的文本教材；每轮提问只使用当前可访问书籍的分块，可进一步限定章节。

主体为 Flask + SQLite + 原生 JavaScript/CSS，前后端同源部署。`self-improvement/` 是独立保留的 OpenClaw TypeScript Hook，不被课程助手导入，也不参与教材检索、用户反馈处理或答案生成。

```text
浏览器：web/index.html + app.js + reader.js + styles.css
    │ 同源 HTTP JSON / POST SSE；Cookie + CSRF
    ▼
Flask：study/app.py
    ├── documents.py：文本解析、章节识别、分块
    ├── rag.py：词法 / FTS5 / 向量融合与语义高亮
    ├── tutor.py：模型主备、结构化输出、问答模式工具循环、引用验证
    ├── reader.py：规范全文阅读块、批注读写与版本校验
    ├── database.py：SQLite 连接、表结构与兼容迁移
    ├── 索引执行器：单线程，进程内排队
    ├── 内置教材播种线程
    └── 反馈汇总线程：启动检查 + 每 6 小时检查
           │
           ├── 持久数据目录：SQLite + sources 原文件
           ├── OpenAI 兼容 Embedding 服务（可选）
           └── OpenAI 兼容 LLM 服务（主模型 / 备用模型）
```

Railway 使用 Dockerfile 启动单个 Gunicorn worker，线程类型为 gthread、8 个请求线程，保持 1 个副本。锁、限流桶、任务队列和信号量都在进程内；增加 worker 或副本会破坏现有协调假设，不能直接作为扩容手段。

## 3. 数据模型与持久化

数据根目录由 `STUDY_DATA_DIR` 决定，本地默认 `.study-data`；容器默认 `/data`。原文件不塞进数据库，而是保存相对路径。

```text
<data-root>/
    study.sqlite3
    study.sqlite3-wal / study.sqlite3-shm（运行时可能存在）
    sources/
        <owner-id>/<book-id>.<extension>
        builtin/<book-id>.<extension>
    .session-secret（本地未显式配置密钥时生成）
```

| 表 | 保存内容与边界 |
| --- | --- |
| `users` | 用户名、大小写归一化唯一键、密码哈希；包括共享教材的系统账户 |
| `books` | 所有者、标题、文件名、源文件路径、索引状态和分块/章节数 |
| `chunks` | 正文、章节、书内序号、可选页码、JSON 向量和向量空间指纹 |
| `chunks_fts` | jieba 分词后的 FTS5 虚表；rowid 对应 chunk ID |
| `conversations` | 按用户和书保存的学习会话 |
| `messages` | 角色、正文、模式及完整 JSON `payload`；引用、结构化答案和检索元数据在 payload 内 |
| `test_codes` | 测试码与永久绑定记录；不随环境变量删除而撤销 |
| `annotations` | 每账户每书的私人批注：正文版本哈希、UTF-16 起止、原文摘录、笔记与颜色；随书/账户级联删除 |
| `feedback` | 每条助手消息当前的一次评价，含可选原因 |
| `feedback_archive` | 追加式评价事件，包括改评、撤销及问题前 120 字 |
| `feedback_stats` | 已完成的三日周期计数及 Top 10 差评原因/问题 |
| `app_logs` | 短期操作日志，读写时清理超过三天的记录 |

SQLite 开启 WAL 和外键，连接具有 30 秒锁等待。删书级联分块、会话与批注，删会话级联消息，删分块触发 FTS 清理。反馈三张表没有外键，不会随会话删除自动清除；账户/内容彻底删除需要单独考虑反馈留存。

阅读器的规范全文不进数据库：由源文件在内存中重建，按书缓存少量快照（3 本 / 64 MiB 上限，解析前后复核源文件未中途变更），版本为其 SHA-256；批注表通过该版本哈希与正文对齐。

共享书下的对话所有者与书所有者不同，因此会话外键关联书 ID，不要求二者 owner 相等。数据库外键不能代替应用的所有权校验。旧复合外键由 `_migrate_shared_books` 兼容迁移；当前不是独立迁移工具或完整的版本化迁移系统。

## 4. 权限与请求安全

登录使用 Flask Cookie 会话，密码采用 PBKDF2-SHA256 哈希；会话期限 7 天，HttpOnly、SameSite=Lax。Railway HTTPS 环境使用 Secure Cookie。非 GET/HEAD/OPTIONS 的 API 请求校验 `X-CSRF-Token`，登录和注册也不例外。

教材查询限定 `owner_id IN (当前用户, builtin)`；会话和消息继续限定当前用户及书籍。共享的是教材，不是用户对话。不可访问的书、会话或分块返回 404，避免直接暴露其存在。

普通用户对内置教材的删除、重新索引和原文件下载会得到 403；内置教材正文仍可在阅读器阅读。私有书这些接口仍然存在，即使页面没有显示删除/下载按钮。权限必须由后端执行，不能依赖隐藏按钮。

日志存在有意的共享范围：用户能读取自身记录、`builtin` 系统记录以及全局 `login_failed` 记录；登录失败详情包含提交的用户名。不能将日志描述为完全按账户隔离。页面“开发者模式”只是本地显示诊断信息的开关，不是管理员角色。

## 5. 教材进入索引的链路

1. 上传端点检查格式、大小、账户容量及并发限制，保存原文件和书记录。支持 UTF-8 / UTF-8 BOM 的 `.md`、`.markdown`、`.txt` 与 `.docx`；DOCX 在服务端用标准库转换为 Markdown（样式与启发式标题识别、文本框去重）。
2. 单线程索引执行器读取正文，保留章节层级，默认按 1200 字符分块、重叠 160 字符；重叠不跨章节。图片、远程链接内容与扫描 PDF 不进入索引，也不提供 OCR。
3. 保存正文与 FTS5 分词；配置向量服务时批量生成 embedding，失败时保留词法/FTS 路径并记录降级。
4. 更新 `queued → indexing → ready/error`。启动时将遗留的 queued/indexing 标记为 error，不自动恢复原来的内存任务。

分块 `ordinal` 是书内位置，chunk ID 是数据库标识，两者不能互换。当前文本解析没有可信页码，`page` 为 null，不能把分块号显示成教材页码。

内置教材启动扫描 `builtin_books/` 的直属受支持文件，以文件名去扩展名后的标题查找共享书。仅“ready 且源文件字节一致”跳过。重建已有内置书会先删除该书所有用户对话；更换文件、改名、移除文件和更换向量模型各有不同后果，见[维护说明](MAINTENANCE.md)。

## 6. 检索与生成链路

### 6.1 范围优先

先从 SQL 取得当前书、可选章节的候选分块，FTS 查询使用相同范围，再进入检索算法。不会先跨账户或跨书检索再交由模型自行筛选。问答模式下模型自主发起的每次工具检索也经同一闭包进入该范围，工具本身不能越出当前书与章节。

最近三个历史用户问题仅用于指代消解；检测到“继续、刚才、它、举例”等词时，将最近问题前 300 字拼入检索查询。模型接收近期问题，不接收完整历史助手回答。

### 6.2 三通道融合

`terms()` 使用 jieba 搜索分词、去停用词及单字符，查询最多保留 64 个词。检索由以下通道组成：

| 通道 | 候选依据 |
| --- | --- |
| 词法 | 连续词串、英文整词、中文二/三字片段匹配；分数至少 0.12 |
| FTS5 | OR 词查询按 BM25 排序，最多 24 项，并再次限制为允许范围且词法分数至少 0.12 |
| 向量 | 归一化向量点积，空间指纹与维度相同才比较，余弦至少 0.55 |

各通道按 `Σ 1 / (60 + rank)` 等权 RRF 融合，默认返回最多 6 个分块。词法和向量各最多取 18 个候选；融合门槛在向量生效时为 0.02，否则为 0.015，向量相似度至少 0.72 可放行。参数详见 `rag.retrieve`，它们不是环境变量。

向量以 JSON 保存在 SQLite 中，查询时 Python 遍历候选计算点积，没有向量数据库或 ANN 服务。空间指纹包含实际 embeddings URL、模型名及维度；维度相同不代表不同模型的向量可以混算。向量不可用时返回 `degraded=true`，仍可通过词法/FTS 回答。

在 explain/outline/quiz 模式中，如果去停用词后没有有效检索词，则从范围内按位置抽取最多 6 段，并标注 `selected-excerpts`。这是抽样辅助学习，不是完整章节或全书覆盖。

### 6.3 问答模式：模型驱动的工具检索

qa 模式不再固定「一次检索 → 生成」。`Tutor.agent_stream` 以原生 OpenAI `tools` 参数向模型暴露唯一工具 `search_book(query, limit)`（`tool_choice: auto`；请求不带 `response_format`，它与其他供应商的 tools 支持冲突），由模型自主决定检索词、次数与何时作答。explain / outline / quiz 仍走固定检索管线。

- 预算：工具调用累计上限 `AGENT_MAX_CALLS`（10 次）、循环上限 `AGENT_MAX_ROUNDS`（12 轮，为自动补检轮与作答轮留余量）。超限调用不执行检索，向模型返回 JSON 错误消息；系统提示词中写明的次数上限必须与常量同步修改。
- 证据池：工具命中的分块按首次出现顺序分配 C 编号并在轮次间保持稳定，模型换词重搜不会使已给出的引用失效；重复命中保留原编号。
- 安全网：模型不调工具且证据池为空时，自动以原问题检索一次；请求异常且本轮无内容时同供应商盲重试一次；切换备用供应商时重建与供应商无关的上下文（system + 原问题 + 证据池）并重置轮数，不携带原供应商的工具转录；整体失败且未流出任何可见增量时，应用层透明回退固定检索管线。
- 过程记录：应用层把每次调用记为 step `{query(≤60 字), count, auto?, error?}`（自动补检与被拒调用也入列），经 SSE `status(stage=search)` 实时下发并随回答持久化到 `retrieval.steps`，`searches` 即 steps 数量；每次调用另写一条 `agent_search` 应用日志（被拒调用为 warning 级）。
- 流式预览复用 `_visible_stream_text`：最终 JSON 的 `paragraphs` 出现之前，模型的中间叙述不会外泄到页面。

### 6.4 结构化生成与主备模型

命中分块被分配本轮 `C1…Cn` 标签。模型输入为当前书名、问题、模式、历史问题和证据，输出普通段落或自测条目 JSON。无命中时直接返回依据不足，不调用模型。

`Tutor` 按主模型、备用模型顺序调用。一次性生成遇到请求、结构或引用错误可切备用；流式路径只有在首个可见正文增量之前失败才可切换，避免拼接两份回答。应用层在整个流式尝试未产生可见增量时，还会尝试一次性生成，因此不能假设每轮只调用模型一次。问答模式的工具循环在 tutor 层有同等的供应商重试与交接逻辑（见 6.3），回退顺序为：工具循环 → 固定检索的流式 → 一次性。

解析器可从思考文本或代码围栏中提取 JSON，并有限修复字符串内未转义引号。空正文可尝试 reasoning 字段，但不会直接展示完整思考过程；截断或无法解析的回答仍然拒绝。

### 6.5 引用验证的保证范围

`validate_answer` 验证模式、条目数量、必需文本和本轮证据标签；每个段落或自测条目都必须有引用。普通段落内嵌 `[Cn]` 优先于引用数组；旧数组式引用仍兼容，自测文本中的标记会剥离后通过条目引用显示。

`grounded=true` 只表示通过这些结构及引用标签检查，不表示每句推论都被证据蕴含，也不表示法规为最新版本。没有独立事实核验模型或逐句法律有效性核验。

最终回答成功后，问题和答案在同一事务中保存，再发送 `answer` 事件。失败轮次不保存这两条消息；流式预览可能已经展示了尚未通过最终校验的文本。

## 7. 浏览器状态与原文阅读器

前端使用单个 `state` 管理账户、书、章节、对话及流式状态。`epoch` 和 AbortController 防止切书、退出后旧响应覆盖新页面；右侧面板另有递增序号防止异步打开串位。停止按钮取消浏览器等待，不保证取消远端生成或节省费用。

SSE 使用 POST fetch 读取流，而非 EventSource。正文增量约每 60ms 合并渲染；问答模式等待期间，每次 `search_book` 调用以编号状态行实时呈现，回答完成后收敛为消息下方默认折叠的「模型自主检索 N 次」轨迹（含被拒调用计数）。最终结构化答案负责显示行内引用与反馈按钮。

点击引用即打开原文阅读器（`web/reader.js`）：按 anchor 把引用分块映射到正文块并加底纹标记，映射校验 ordinal、章节、页码与文本全等，失配返回 409 提示正文与索引不一致。阅读器支持目录跳转、滚动到边缘时按 start 前后追加正文块；阅读偏移一律以 UTF-16 为单位，正文版本为规范全文的 SHA-256。

选中文本可创建私人批注（黄/蓝/绿三色高亮与笔记，重叠批注收入抽屉）；批注按账户隔离、随书级联删除，创建时校验摘录与正文全等，正文版本变化后旧版本定位拒绝写入并返回 409。全文阅读与批注不调用模型或 embedding；阅读器只帮助人工阅读，不改变原回答引用、重新检索或向模型补充上下文。后端保留的分块详情、邻块与语义整句匹配端点仍是公开 API，但前端阅读器已不使用。

`study.devMode` 与 `study.deskLayout` 保存于 localStorage，分别控制诊断显示和书架/阅读栏布局；学习记录仍保存在服务端。

## 8. 反馈与数据闭环边界

`feedback` 是当前状态：1 满意、-1 不满意、0 删除当前评价；原因仅用于不满意，最多 200 字。更新评价不更新其原创建时间，因此不能把该时间当作最后操作时间。

`feedback_archive` 是事件历史：每次有效提交都追加，包括重复提交、改评和撤销。问题仅保留前 120 字，没有完整回答、引用和模型配置的不可变快照；旧的当前评价也没有自动补录为历史点击。

`feedback_stats` 从首条归档时间起划分连续 72 小时半开区间，启动和每 6 小时检查一次，仅汇总已结束周期，可补算停机期间的周期。计数是全局满意/不满意/撤销事件数，差评原因和问题各保存 Top 10；不是独立用户数、去重答案数或净满意率。

仅 `app_logs` 执行三日过期清理，归档和统计不受该清理影响，但仍依赖持久卷及备份。统计没有独立管理 API/报表页面，系统日志只显示周期计数。现有反馈支持人工审查和后续评测集建设，没有自动训练、微调或修改检索参数。

## 9. 隐私与尚未实现的能力

教材源文件、账户哈希、对话、批注及反馈均可由部署管理员访问，不是端到端加密。启用 embedding 会发送教材分块、检索问题及语义定位文本；生成会向主模型或备用模型发送命中证据和问题。备用服务也必须被纳入数据使用授权范围。原文阅读与批注不调用模型或 embedding 服务；批注内容只保存在服务端数据库，按账户隔离。

当前不包括邮件验证、密码找回、管理员面板、跨书联合检索、PDF/OCR 导入、学习计划、错题本、计费、自动反馈训练、可靠后台任务队列或分布式协调。法律教材用于课程学习，不自动查询最新法律，也不代替专业意见。
